# KULT Fuse v1.9.0 — release notes

Built on v1.8.0. Everything in v1.8's truth boundary still holds: the worker keeps the Velocity key, so Fuse checks submitted targets but can't stop a compromised worker trading directly.

## Fixes

1. **DFlow freshness (supersedes v1.8 item 1).** v1.8 set a quote's age to the time the book sequence last changed. A live but quiet Kalshi book is therefore "stale" 20 seconds after its last trade, and the on-chain `accept_observation` rejects it for the same reason, so a normal market could almost never authorize an increase. v1.8 also threw `oracle replay rejected` whenever a poll returned the same sequence, which is most polls.
   v1.9 keeps v1.8's fail-closed rules (no sequence, metadata fallback, first snapshot, sequence going backwards: display only) and changes two things:
   - age = fetch time, but only while the book has visibly advanced within `DFLOW_MAX_BOOK_IDLE_SEC` (default 900 s). A frozen or cached feed fails closed after that window.
   - an unchanged sequence is the same observation: the engine holds with `ORACLE_UNCHANGED`, sends nothing on-chain and never counts it as a confirmation. A rewound sequence holds with `ORACLE_REPLAY`.
2. **Loss-stop P&L gap.** With a loss stop set and venue P&L unavailable, v1.8 skipped the whole tick, including a probability kill. v1.9 blocks increases only; kills and step-downs proceed.

## Experience

- **Be the agent:** a public `GET /api/agent/check` and a box under the curve. Ask for an exposure, see allowed or refused with the reason in plain words, drawn on the curve. Works in setup mode against the committed policy (marked preview). Never trades. The operator-only precheck panel is removed from the page; `POST /api/agent/proposal` is unchanged for real agents.
- `npm run smoke:dflow` waits for a book update before passing, so a pass proves the feed is live.

## Tests

82 pass. `tests/hardening-v19.test.mjs` adds five; all five fail against v1.8's `src/` and pass on v1.9. Three v1.8 tests were updated where they asserted the old behaviour (throwing on a repeated sequence, the first-tick P&L skip).
