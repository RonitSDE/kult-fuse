# KULT Fuse v1.9.1 — UX hardening and hackathon deployment handoff

## What changed

1. Clearer product promise and four-stage guided flow: allowed proposal → hard-cap refusal → killed mandate → refused reopen. The guide **never trades**.
2. Top-level `SIMULATION · NOT EXECUTED` / `VERIFIED RECEIPT REPLAY` / `SYNTHETIC UI PREVIEW` modes. No simulated venue positions/P&L are displayed as real. Synthetic fixtures are named clearly in execution-proof areas.
3. Readable small-screen probability-threshold table replaces shrinking the SVG chart on narrow devices; desktop keeps the full SVG.
4. Venue-authority trust limitation is now above the fold. The worker still holds the Velocity signing key; Solana Fuse checks only instructions it receives. A killed mandate does not itself close a trade.
5. Separate proof/receipt panels remain dependent on **real verifier data**. No generated trade hashes or fabricated fills added.
6. `.mjs` MIME types added to both HTTP and UI preview servers for the new reusable view logic.

## Dev deploy (short)

```bash
# Node 24 on a networked CI runner
npm ci
npm test
npm run preflight
# Compile Anchor 0.31 program + run local validator integration tests
# Configure devnet DFlow market, Velocity devnet account, contract/program IDs
npm run submission:check -- --url https://YOUR_PUBLIC_URL
```

Provide: public app URL, Solana program ID and IDL, onchain mandate create/arm/target/kill signatures, **real** Velocity open/resize/close venue receipts, verified flat position after kill, independent proof verifier output, tagged commit SHA and green CI link.

## Release decision

- UI demo and policy unit tests: **passed** with synthetic fixture.
- Mainnet with user funds: **NO-GO**; venue signing authority is not bound to Fuse, and the real trade/close journey is not independently validated.
- Hackathon submission: **pending** real devnet fills, deployed program, public URL and a video recorded from the tagged build.

Do not call a guided simulation a Solana rejection. Demonstrate an actual onchain refused instruction separately when a deployed program exists.
