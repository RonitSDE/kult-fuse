# KULT Fuse v1.10.0 — Kalshi read-only context + accountable decision history

## What changed

**Backend:**
- `src/adapters/event/kalshi-observer.mjs` polls Kalshi public **Predictions REST** market and fixed-point orderbook responses, not signed account/trading routes. It uses the ticker already selected from DFlow; invalid/missing tickers and upstream outages produce a non-authoritative `UNAVAILABLE` state. Fixed official hosts; 4-second timeout; 128KB body cap; 30-second cache.
- `GET /api/market/context` shows DFlow as **the sole** signal controlling the Fuse policy, alongside the advisory Kalshi market status, midpoint, spread and price divergence. Kalshi data is **not** an oracle and never authorizes or refuses an actual Fuse action.
- `src/core/decision-journal.mjs` plus `GET /api/journal` project the current mandate's bounded worker decisions and stored venue receipts. Logs are labeled `WORKER_LOG_ONLY`, captured receipts `CAPTURED_UNVERIFIED`; the browser only upgrades a receipt's label after matching a hash from a verified-run proof. No false claims about venue closings, true P&L or safety assurances.

**Frontend:**
- Clear market comparison panel, expiry/freshness context, and manual read-only reference refresh.
- Agent Decision Journal with All / Risk / Execution / Lifecycle filters, decision and receipt counts, evidence labels, and explorer links only for plausible live Solana signatures. Both sections explicitly switch to synthetic labels in preview / guided demo.
- Mobile view stacks market panels and uses a two-column accountability grid, preserving v1.9.1's mobile mandate thresholds.

## Explicit limits / no scope expansion

1. **Velocity private signing authority remains with the worker.** Fuse cannot enforce every venue trade against a compromised worker; kill requires a separately verified close.
2. The newly added Kalshi REST integration is PUBLIC, READ-ONLY and OPTIONAL. Kalshi does not sign transactions, supply the execution oracle, or place contracts through this build. DFlow is the only active policy signal.
3. The Decision Journal is an interpretation of operational logs and captured receipts. It is *not* a permanent independently-audited ledger unless corresponding signatures and verifier checks are present.
4. `docs/devnet-proof.json` is historical and has not been turned into Velocity fill proof. No fresh Solana devnet deployment, compiled IDL, executed live position lifecycle, public URL or submission video has been claimed.
5. No mainnet trading approval. This is a **Solana devnet integration candidate**.

## Test / release gate

- `npm test` for policy, replay, risk, evidence, Kalshi input hardening and journal behavior.
- Run `npm ci` with **Node 24** on the developer's networked runner. Use `anchor build && anchor test` and an actual Solana devnet deployment for the program.
- Use `npm run preflight`, `npm run smoke:dflow`, `npm run proof:venue` and `npm run verify` only when relevant credentials/configuration exist.
- `npm run submission:check -- --url https://YOUR-PUBLIC-URL` must be green on the **exact tagged SHA**. Do **not** fill proof fields with fabricated signatures or fixture results.

Sources: official Kalshi predictions REST market data and orderbook documentation, official DFlow prediction market interface. This integration intentionally uses read-only REST over signed Kalshi WebSocket/FIX/Perps lanes.
