# Go-live and proof checklist · v1.8

Every step ends in something you can link. Do them in order on one cluster (devnet).

1. **Build and test.** `npm ci && npm test`. In `contracts/fuse-anchor`: `anchor build && anchor test`. Deploy (`anchor deploy --provider.cluster devnet`), keep the upgrade authority safe, copy `target/idl/kult_fuse.json` to `deploy/idl/kult_fuse.json` and commit it. Never reuse v1.2 mandate accounts.
2. **Pick the signal.** `npm run markets` (or `-- --series <KALSHI_SERIES>` / `-- --search <words>`). Choose a liquid market whose YES outcome implies a SOL long and closes after your demo. Write that event → SOL rationale (80+ characters) into `SUBMISSION_MANIFEST.json`. Set `DFLOW_MARKET_MINT` and run `npm run smoke:dflow`: it watches until the book moves, then prints `DFLOW SMOKE PASS`. If the book never moves in 5 minutes, pick a more active market.
3. **Fund the venue.** Create a dedicated wallet, put its key in `VELOCITY_PRIVATE_KEY_JSON`, give it ~0.1 devnet SOL, then `npm run venue:setup -- --fund 25`. It mints dUSDT from the devnet faucet, creates the Velocity account and deposits. If the faucet mint fails, get dUSDT from Velocity's devnet channel and re-run without minting.
4. **Configure the host.** Fill `.env` from `.env.example`: program id, three distinct Fuse keys, venue key, `FUSE_ADMIN_TOKEN` (24+ chars), a dedicated devnet RPC, `BUILD_SHA=$(git rev-parse HEAD)`, `BUILD_TAG`. `npm run preflight` must pass. Keep `AUTO_WORKER=0` for now.
5. **Dry-run the proof.** `npm run proof:venue -- --dry-run` checks wallets, collateral and the market. Then `npm run proof:venue`: open → resize → over-cap refused on-chain → kill → close → post-kill target refused → settle. It writes `docs/venue-proof.json`; check it with `npm run verify -- --file docs/venue-proof.json`. The probability path in this run is scripted and labelled so.
6. **Deploy.** `deploy/Dockerfile` (Node 24, glibc) or `render.yaml` (paid instance with a persistent disk; the worker must not sleep). Without config the page opens in setup mode and lists what's missing, so a half-configured deploy is never a blank page. `/healthz` returns `status: "ok"` once live.
7. **Run it live.** Sign in as operator, arm, and let the worker trade on the real quote (`AUTO_WORKER=1` after one manual tick works). Trigger the kill either by the market crossing the line or with Emergency kill, and confirm the venue close and residual on Velocity.
8. **Record and gate.** Record the demo from the public URL in a clean browser: live quote, curve, a fill, the verifier, the kill, the trust boundary. Fill the manifest with observed links only, then `npm run manifest:source`, `sha256sum -c SOURCE_MANIFEST.sha256`, `npm run release:check`, and `npm run submission:check -- --url https://YOUR_HOST`. The gate can't invent missing proof; it only checks it.

If an order times out, read the actual Velocity position and history before retrying. A killed mandate with residual exposure needs a venue close and an alert. A Fuse kill alone is never a flat position.
