# KULT Fuse v1.8.0 — Hackathon hardening / developer handoff

## Scope and truth boundary

This is a **source candidate for a Solana devnet demonstration**, not a deployed or independently verified trading application. The onchain program can check worker-submitted exposure targets, but the worker retains a Velocity trading signing key and can bypass that program. Authority binding requires an audited venue-supported PDA/delegate order path and negative tests against actual Velocity. Never describe this version as cryptographically preventing a compromised worker from trading.

### Source changes since v1.7.0

1. **DFlow real freshness** (superseded in v1.9: see docs/v1.9_RELEASE.md): repeated orderbook sequence is the *same* observation. The first book snapshot after startup is also view-only until an advancing upstream sequence is observed. Sequence-less book or metadata fallback is view-only (`ORACLE_UNVERIFIED`). A moving local polling counter is no longer an oracle. The book receive-time is retained until a genuine sequence change; its timestamp is only local receipt time, **not** proof of the exchange's source wall-clock update.
2. **Risk checks:** future-dated/missing quote times are rejected; missing or invalid venue P&L blocks new trading risk when a loss stop is configured. Venue collateral and the mandate's max-leverage setting are checked before *each* Velocity size increase, including after a worker restart. These checks are operational, not venue or Solana enforced.
3. **Agent intent preview:** authenticated `POST /api/agent/proposal` receives a `targetUsd` intent bound to the current `fuseId` and `policyHash`; returns `ALLOW_AS_PROPOSAL_ONLY` or `REFUSE`. It never signs an order, alters a mandate or returns a trade receipt. Run `npm run agent:demo` for an OFFLINE illustrative allow/refuse example. There is no actual LLM connection in this package.
4. **RPC verifier protection:** `POST /api/verify` accepts one request at a time, max six per minute globally; no trust in spoofed `X-Forwarded-For`.
5. **Safety and reproducibility:** Node preflight requires 24 (matching package.json); distinct operator/owner/oracle/exec role credentials checked by preflight; unreviewed mainnet Velocity execution disabled by default.

## How to reach the submission gate

A. On a clean **Node 24** runner with registry access:

```bash
npm ci
npm test
npm run preflight
cd contracts/fuse-anchor && anchor build && anchor test && cd ../..
```

B. Choose one *actual* DFlow Kalshi YES mint; record market event rules, liquidity, expiration, and a defensible link from the YES probability to SOL-PERP in `docs/MARKET_THESIS_TEMPLATE.md`. A live quote should show increasing upstream `bookSequence` on real market updates. If the feed never includes a sequence, **do not loosen freshness checks to force a trade**; change to a documented source with trustworthy update semantics.

C. Deploy the **source-matching** Solana program/IDL on devnet, configure distinct role keys and Velocity devnet account, fund dUSDT and devnet SOL. Run `npm run venue:setup -- --fund 25` then `npm run proof:venue -- --dry-run` before the real proof runner. Keep mainnet trading disabled.

D. Show: **arm → fresh observation → allowed $ target → genuine Velocity IOC open → resize → onchain over-cap refusal → kill → independent venue close → onchain post-kill refusal**. Confirm the venue position really is flat. Capture actual program and venue signatures with no fabricated links; run `npm run verify` independently.

E. Run from the exact tagged Git SHA:

```bash
npm run manifest:source
sha256sum -c SOURCE_MANIFEST.sha256
npm run release:check
npm run submission:check -- --url https://YOUR_HOST
```

The manifest currently has intentionally empty proof fields. Do **not** fill these using demo transactions or guessed market IDs. The proof runner's probability changes are scripted and must be disclosed in the video; genuine observed DFlow quotes must be shown separately.

## Release criteria

**Current:** core unit/adversarial tests passed in local Node 22; Node 24 install/Anchor compilation/live Solana/Velocity tests not reproduced. This branch must not be approved for real-money trading.

**Before judge submission:** stable HTTPS URL, public IDL, deployed Fuse program and PDA, three real venue fills, onchain refusal and kill receipts, zero residual position, independent verifier green, exact SHA/CI logs, short video with explicit unbound-venue-authority disclosure.

**Before production/mainnet:** audited PDA/delegate trade authorization, strict account constraints, collateral/leverage/PnL oracle controls, incident monitoring, emergency revocation, external security review, and staged loss-limited rollout.
